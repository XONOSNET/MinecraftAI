# First eligible attack · training-only protocol v1

**Question:** Can the existing combat helper land a hit before the zombie hurts the bot if the opening proposal arrives earlier? This experiment tests one proposal, leaving all movement, re-aim, reach, sight, cooldown and critical-attack checks intact. No production controller or policy changes.

**Matched starts and budget:** 12 paired zombie starts, 24 encounters, in this order:
`10311180, 10737471, 10192716, 10572246, 10362703, 10882707, 10560339, 10550370, 10816047, 10080307, 10330461, 10637136`. These are Random(170210).sample(range(10_000_000, 11_000_000), 12) and disjoint from the v1 training, holdout and temperature-probe domains. Alternate control-first / intervention-first, starting with control. One bot, one CPU thread, 18 minutes checked between fights, no retries. The same native Normal/iron/20 HP/20 food reset, geometry, and stop criteria as v1 apply. Native mob AI is not synchronized by seed. Freeze the original v1 baseline tensor fingerprint `6b167faf6d664abf34158fe125dff337011c4679f1ef7a9fb0a179610abf30e6`, controller and settings. Stop the block if a fixture or recording check fails, server becomes unavailable or busy, RAM reaches 86%, or the lab is intentionally stopped. Preserve incomplete rows without claiming a result for the block.

**Treatment:** Both arms always compute the same saved-policy argmax. In the intervention arm, at the first observation with target present, visible and within 3 blocks, iron sword equipped, and cooldown exactly zero, submit attack (6) once. This applies whether or not the bot has already taken damage. If the underlying proposal was already attack, record a trigger without a changed action. If the helper declines, count the refusal and never retry the intervention. After the trigger, execute the saved policy normally. Observe the first eligible window in both arms. No other observations, actions or outcome rules change.

**Primary outcome:** Fraction of all assigned fights with a confirmed owned-target hurt before first observed bot damage. Use native target damage receipt and bot health-loss receipt, on one monotonic fixture clock. If the mob's native damage packet indicates an earlier/conflicting damage order, or either relevant timing gap is ≤50 ms, report ambiguity. A confirmed hurt with no bot damage is a success. A native win with no confirmed target hurt is ambiguous; no hurt and no win is a failure. Report ambiguous fights, events and raw classifications separately. For the gate, count ambiguous intervention outcomes as failures and ambiguous control outcomes as potential successes. Decisions are based on client-observed order; this cannot establish exact server hit time.

**Minimum worth pursuing:** At least 3 extra first-hit successes out of 12 (+25 percentage points using the conservative bound), with no more deaths or escapes, no fewer wins, and no increase in mean total damage. This is a practical training-only screen. Report actual proposals, requests and confirmation receipts including gaps between decisions, whether the first eligible observation changed the selected action, and how many interventions were refused, requested after damage, unconfirmed, or followed by later damage. A later hurt packet is only consistent with the intervention when no competing request intervened. Do not infer that every swing should have prevented damage.

**If it passes:** Train a small opening decision head using only eligible observations and outcomes from these encounters. Use attack-vs-base targets from opportunities with successful, plausibly attributable execution versus refusals, unconfirmed/late execution or no opening benefit. Keep the saved policy for the rest of the fight, using the head's own choice at the first eligible observation, without a forced attack. Compare to frozen control on eight disjoint new training-only pairs and keep safety gates before considering any sealed or new holdout. Record missing counterfactual labels and class balance rather than treating all forced attacks as positive demonstrations.

**If it fails:** Keep the saved reference. Use the first-event trace to identify whether the opportunity was already late, the helper refused, a request was delayed or unconfirmed, or a landed hit was followed by damage. Do not spend either reserved v1 holdout block or train an opening head from an unsuccessful intervention.
