# First Night completion investigation

The latest completed student baseline had 8/8 huts, torches and provisions, three beds, and zero resource round trips. Its measured average lesson progress was 83.42%, while full-sequence completion remained 0/8. The prior accepted comparison improved partial progress from 72.23% to 74.87%; these are assisted-chain milestone scores, not unassisted general survival success. Teacher runs also failed to finish, establishing that more policy training alone was insufficient.

Four controller defects were found:

1. Moving animals consumed all 96 resource-memory entries. Every bot in the latest completed teacher batch had only food/wool sightings left; its home, wood and stone records had been evicted. Scouting specifically required a remembered wood/stone location, so the two teacher bots reaching scouting explored for 1,295 and 1,040 seconds without a usable landmark. Nearby animal sightings now merge into search patches, and home/wood/stone/food/wool have separate bounded budgets. Search no longer deletes an exhausted wood landmark, although it excludes exhausted resources from acquisition destinations. Scouting prioritizes nearby remembered resources, releases blocked approaches and reports missing landmarks after 30 seconds instead of falling back into endless wood exploration.
2. A locked animal bypassed location rejection. When its checked route failed, the controller rejected its location but retained its target ID; the next tick explicitly allowed the same locked target. Unreachable animals now lose the lock and receive a 30-second entity-ID cooldown, so moving does not bypass rejection. Lambs are excluded from white-wool targets because they do not drop wool. No animals or inventory were granted to production bots.
3. Home could be outside client-loaded chunks. A saved teacher return reproduced a known-safe incomplete route toward an unloaded destination, but the controller discarded it and remained stationary. Unknown home doors now use an exterior approach. For an unloaded destination only, a reversible checked path of at least four nodes making at least four meters of improvement can supply a maximum 12-waypoint prefix. It replans as chunks load; every cell retains existing terrain, bounds and player checks, and arrival still requires reaching the real destination. Known solid blocked destinations cannot use this fallback.
4. Door interaction used distance without visibility. At a diagonal house corner the controller paused movement and repeatedly clicked a door hidden behind the front wall. Opening now requires an actual clear ray to the door; otherwise the checked route continues into the approach aisle.

Validation: all 291 JavaScript tests passed. Tests cover memory flooding/persistence, exhausted-landmark preservation, unreachable moving sheep, lamb/sheared exclusion, actual two-leg scouting credit, explicit missing-landmark failure, unloaded-route prefixes with blocked-goal protection, and occluded door interaction.

Native evidence:

- `endgame-native.json`: isolated fixture, empty diagnostic inventory before equipment setup; three real adult sheep and a real tree landmark. The bot collected three white wool in 4.512 seconds, then visited the observed landmark and returned through the door in 8.977 seconds. The test stops at `night_hold`; it does not credit a completed production survival trial.
- `endgame-return-native.json`: the saved teacher return previously stayed stationary for the full 8.5-second replay. With the fix it physically reached its home destination in 44.506 seconds while loading terrain along the way.

Native checks use teacher intentions through the shared motor without learning API writes. Fixture blocks, tagged animals, dropped items, diagnostic inventory and operator permission were cleaned up. Early diagnostic attempts exposed fixture setup errors (missing surface callback, inappropriate fixture height for combat, and an extra floor in a hollow cube); corrected final runs begin with verified empty volume and empty inventory.

Automatic learning was paused and any unvalidated bundle restored before deployment. Only Node bots restart. Resume options in `logs/endgame-resume.json` preserve First Night level 1, scenario 2, size 128 and automatic progression, with a fresh baseline/candidate comparison under the same controller. Model checkpoints, training data, bot identities, user configuration and unrelated edits remain intact. Reliable full policy completion is still to be measured.
