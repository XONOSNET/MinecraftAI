# LAN dashboard HTTPS

Open `https://SERVER_LAN_IP:8000/` from another PC on the same local network. Replace `SERVER_LAN_IP` with your lab computer's local IPv4 address and `LAN_SUBNET` with your network's subnet. See [local network setup](network-setup.md) before enabling LAN access on a new installation.

After generating a certificate for your own installation, copy its generated `docs/dashboard-lan-ca.cer` to that PC. In Windows, open the certificate, select Install Certificate, Current User, Place all certificates in the following store, and Trusted Root Certification Authorities. This trusts your lab's local certificate authority. Only the public certificate is copied; the server private key stays in ignored data/dashboard-tls. Restart the browser after importing if needed.

The frontend listens only on SERVER_LAN_IP, accepts only the configured subnet and same-origin requests, and proxies to 127.0.0.1:8000. Local HTTP access remains available. LAN dashboard visitors have the existing dashboard administration controls; use only your trusted home network. There is no router port forwarding.

Start-Lab starts the HTTPS frontend; Stop-Lab stops it. Before running `scripts/Enable-DashboardFirewall.ps1` as Administrator, adjust its local address, subnet and interface alias for your machine; the helper currently contains deployment-specific defaults. The firewall rule should allow TCP 8000 only on your chosen adapter, local address `SERVER_LAN_IP`, and remote subnet `LAN_SUBNET`. The local server certificate must match your configured address. Generate and trust your own installation's certificate rather than relying on the repository's historical public CA certificate. The local server certificate is valid for one year; a regenerated CA must be trusted again on other PCs.
