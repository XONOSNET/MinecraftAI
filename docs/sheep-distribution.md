# Sheep distribution and rollout recovery

The queued controller rollout completed the evaluation and paused terrain preparation, then failed because it invoked legacy Windows PowerShell, where execution policy disallowed the bot-launch script. Models were safely restored and learning stayed paused. The helper now preflights PowerShell 7 before pausing and uses that host (the same available runtime used for successful lab launches). No execution policy is changed.

Sheep replenishment now considers observed roads across the full bounded trial site and varied real route elevations, instead of limiting candidates to a 48-block radius and eight blocks of camp elevation. Spatially spread sampling retains up to 128 patches rather than the closest 64. Every wave also tries four regional surface candidates. Sheep require actual spawnable grass support and two air blocks, avoid players within eight blocks and other sheep within six, and remain outside house plots. The whole-site loaded sheep cap remains 24 and each wave can add at most two sheep. Assessment runs still receive no replenishment.

Birth accounting now counts sheep bearing a temporary per-wave tag after each conditional summon, rather than adding execute-success callback scores. Explicit zeroing prevents stale counts after failed conditions. Final birth and population counts are queried back from Minecraft and parsed from the server log; the dashboard reports confirmed last-wave births, trial births and loaded sheep. Missing acknowledgement produces an explicit timeout, not an invented count.

Validation: all 285 Python tests passed, including distribution across explored outer terrain, acknowledged birth counts, assessment exclusions and existing terrain reset protections. The dashboard JavaScript checks passed. An isolated native fixture verified successive sheep waves produced exactly 2/2, 1/3 and 0/3 (births/population) under a population cap of three. Fixture terrain, sheep and drops were cleaned up. No production trial inventory or results were modified. Native result: docs/fauna-distribution-native.json.

The user explicitly authorized resuming the paused lab. Restart deployment includes the already-tested sheep targeting and floor-placement recovery changes. Checkpoint fingerprints were saved before restart to logs/sheep-distribution-models-before.json. Saved settings remain First Night level 1, site scenario 2, size 128 and automatic progression enabled.
