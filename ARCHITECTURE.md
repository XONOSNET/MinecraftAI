# Architecture

Paper 1.21.4 / Java 21 owns a persistent survival world. Eight configurable Mineflayer clients represent ordinary players. Node controls movement and samples observations every five local physics ticks. FastAPI/PyTorch performs batched-by-request CPU inference and explicit training. SQLite separates spatial observations from network weights. A local dashboard reads live telemetry.

## Observation boundary

The navigation perception module performs first-intersection raycasts using actual block collision shapes. Rays originate at eye height, horizontal FOV 90°, vertical FOV 60°, range 16 blocks, 256 rays. Empty block shapes do not occlude. The navigation input has no neighboring-block disclosure. Broader skills additionally use explicitly bounded local foot/head/hazard probes 0.35–1.4 blocks away and a first-solid overhead-cover check within six blocks; these are additional proximity sensors, not unrestricted chunk access. Only first-hit blocks enter per-agent memory. This is a collision-surface sensor: transparent solids still occlude and fluids/noncollision vegetation may not. Entity ray intersections are not yet implemented. Loaded terrain is available to the controller library, but neither the policy nor teacher receives unrestricted chunk data.

512 numeric ray features pool into 32 depth/occupancy pairs. Add goal bearing sin/cos, normalized horizontal distance, health, hunger, ground contact: 70 float32 inputs. The navigation policy has one tanh hidden layer of 128 units and four action logits: forward, turn left, turn right, forward+jump. 9,604 trainable parameters, 38,416 raw float32 weight bytes. Optimizer and serialization add storage. SQLite memory is external and not counted as learned parameters. Memory is currently recorded but not used by the policy; no memory-assisted claim is made.

## Training boundary

Behavioral cloning with Adam, lr .003, minibatches 128, 100 epochs. Teacher labels come from observations gathered during legitimate player movement. A privileged curriculum reset sets individual starting positions and goals at episode boundaries; the policy cannot teleport or issue server commands. Arena construction is explicit administration in a new research world. The shared world never resets per episode. Evaluation course is 80 blocks away, held out from demonstration collection. The original navigation courses are flat: their results measure heading/goal control, not terrain reasoning; broader-task results are labeled separately. Evaluation agent seeds match between baseline and trained runs. Concurrent agents can interact, so scheduling and collision differences remain a confound.

Reward is clipped progress minus .01 per decision; currently logged, not optimized. Reinforcement learning, evolutionary selection, recurrent state, personality-based goal selection, natural-world food foraging, crafting and combat remain future milestones.

Dashboard training jobs clone the active policy and optimizer, take a bounded demonstration snapshot, and learn on one background worker. Status reads do not wait for gradient training. The candidate replaces the active model only when training succeeds and the checkpoint is saved; cancellation leaves the previous policy active. The job exposes preparing/learning/saving/completed/cancelled/failed states, actual pass counts, loss and elapsed time. Browser requests use a strict same-site HttpOnly session cookie with the same origin checks as token-authenticated API requests. The dashboard explains collection, expected pauses, testing and results instead of showing raw API commands.

## Operations

The service owns Minecraft stdin/stdout. Token-protected local POST endpoints provide curriculum control, training, pause, checkpoint, backup, restart and shutdown. No arbitrary console endpoint. Minecraft is capped at 4 GB heap; PyTorch inference is explicitly limited to one thread in each inference worker, with four threads for gradient training. OMP/MKL/OpenBLAS defaults are set before imports. A >90% system RAM watchdog pauses decisions. Maintenance checkpoints and world backups run every ten minutes. Backup waits for the server's save-complete acknowledgment before copying. Automatic bot reconnect is bounded to one connection per identity every five seconds. Server crash recovery is limited to three paused restart attempts. No service installs or automatic Windows boot tasks.


ServerControl serializes background lifecycle operations, pauses learning, saves demonstrations/checkpoints and requests graceful Minecraft shutdown. Watchdog respects intentional stops. Online players come from the Minecraft status protocol, sampled every two seconds; privileges come from ops.json. Authenticated admin endpoints validate names and allowlisted actions without arbitrary console input. LAN bridge limits clients to the configured subnet and eight simultaneous connections.


Curriculum is a persistent state machine driven once per second under the shared service lock. Its phases are waiting, baseline, collecting, training, evaluating, paused and completed. Gradient training still runs in its background worker. Seeds separate teacher routes from held-out evaluations, while baseline and candidate share a per-cycle test suite. Champion checkpoints are separate from rolling checkpoints so retention cannot remove rollback data. Manual learning mutations are rejected while automation owns the experiment. Pause cancels training and restores an unaccepted candidate only after the worker finishes. Finite stage definitions vary distance and heading, with all endpoints contained within dedicated arenas at X=160/240, with forced chunks and acknowledged construction before evaluation starts.


Broader curricula extend the existing scheduler to 32 stages and eight tracks. `lab/tasks.py` specifies owned practice lanes, construction/reset commands and objective success predicates. `controller/tasks.js` measures real inventory/food/coverage/cover, builds 12 additional local features, implements demonstration teachers and bounded dig/eat actuators. Actuators operate only when the selected neural/teacher action requests them; evaluation has no teacher fallback. `lab/skills.py` owns separate replay, weights, optimizer, metadata and protected checkpoints per broader skill. Candidate commits capture their skill identity so pause/cancellation cannot redirect a save into navigation. Champion ownership is persisted for recovery after pauses/restarts. Teacher practice and student practice runs are explicitly tagged; neither advances the autonomous curriculum. Protocol yaw conversion now matches the installed Mineflayer conversion contract, and lane bounds match physical wall faces. Lighting and scoped hostile/phantom cleanup protect controlled practice while preserving world-wide game rules.

Practice hazards have a sealed floor beneath water sources, so source blocks stay within owned fixtures. Broader policy widths are restored from their own checkpoints even if the navigation model size changes. Skill summaries migrate existing replay metadata without eagerly loading every policy.


Cohort configuration is shared through config/agents.json (8 clients, 3 episodes each). A run_config SQLite table records each run's cohort size, preserving historical 15-task comparisons while new tests use 24. Dynamic lane limits and chunked fill commands support up to ten clients. Changing count resets the current stage's promotion streak and begins a fresh comparison on resume.

Observers are a separate 5 Hz console-command worker under the service lock. Persistent named sessions capture the human player's original game mode from bot player-list telemetry and position/rotation in a tagged return marker. Spectator cameras target a training player directly or an invisible non-colliding armor stand. Mobile anchors follow the target; stationary anchors keep their coordinates while turning toward the selected target. Respawn entity IDs and dimensions trigger reattachment. Offline restoration is deferred until the viewer reconnects. Lifecycle operations restore connected viewers before saving/stopping the server; enabled sessions can reattach on reconnect. HTTP accepts only validated names, allowlisted views and bounded numeric offsets.

Replay persistence counts newly recorded samples, not deque length: a full 15,000-example buffer still saves every 100 new examples instead of every action. End-of-session saves remain explicit. This avoids prolonged lock holds during sustained multi-agent collection.

Harvest action 5 returns to forward gaze after digging and can sweep its camera through three pitches when no log is currently visible. This reveals objects through ordinary ray perception; it does not disclose hidden blocks. The teacher alternates close-range scanning with walking toward the pickup area. Larger harvest tasks use compact adjacent trunks and a centered pickup goal.
